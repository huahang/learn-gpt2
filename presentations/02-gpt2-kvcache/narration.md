# GPT-2 推理原理与实现 · 讲解稿

## 第 1 页

大家好，这一期我们一起读懂 GPT-2 的推理过程。所有内容都来自开源仓库 learn-gpt2 里的 gpt2.py 这一个文件。我们先从整体看自回归生成是怎样一步步产生文本的，再依次拆解输入嵌入、Transformer 块、因果自注意力、MLP 和采样。后半部分是本期重点：为什么 KV Cache 能大幅加速推理，它在代码里怎样实现，以及上下文达到上限时，代码怎样处理边界情况。

## 第 2 页

先看全景。GPT-2 的推理是一个自回归循环，代码在 generate 方法里。输入是形状为 B 乘 T 的 token 序列 idx，经过前向计算，得到每个位置在整个词表上的 logits。我们只取最后一个位置的 logits，经过贪心或带温度的采样，选出下一个 token，再拼接到 idx 末尾，进入下一轮。要生成多少个新 token，这个循环就要跑多少次，这正是推理开销的来源，也是 KV Cache 要优化的地方。

## 第 3 页

GPT2Config 是一个简单的配置类，默认上下文长度 block size 是 1024，词表大小是 50257。源码预设了四种规模：gpt2 是 12 层、12 个头、768 维，约 1.24 亿参数；medium 是 24 层、16 个头、1024 维，约 3.55 亿；large 是 36 层、20 个头、1280 维，约 7.74 亿；xl 是 48 层、25 个头、1600 维，约 15.58 亿。四种规模共用同一套代码，差别只在深度、头数和宽度。

## 第 4 页

模型的第一步是把 token 变成向量。wte 是词嵌入表，有 50257 行，按 token id 查表；wpe 是位置嵌入表，有 1024 行，按位置编号查表。两者逐元素相加，就是送入第一层的 x。请注意，位置编号从 start 开始，start 等于 kv cache 的 length。没有缓存时 start 为 0；有缓存时，新 token 的位置要接在已缓存的位置之后。这一点，正是 KV Cache 能正确工作的前提。

## 第 5 页

GPT-2 的主体是 n layer 个结构相同的 Transformer 块，最小的 gpt2 有 12 个，xl 有 48 个。每个块的 forward 只有两行：第一行先对 x 做 ln 1 层归一化，再送进因果自注意力，把结果加回 x；第二行先做 ln 2，再送进 MLP，同样加回 x。这种先归一化、再进子层、最后残差相加的写法，叫 Pre-LN。另外，kv cache 参数也是在这里逐层传给注意力的。

## 第 6 页

接下来看因果自注意力的前半部分。构造函数里只有一个线性层 c attn，输出 3 倍的 n embd 维，一次矩阵乘法就同时算出查询 Q、键 K 和值 V。前向时，split 把结果切成三份，再拆成多个头，形状变成 B、头数、序列长度、每头维度。这里有一个关键观察：c attn 是逐位置计算的，再加上因果性，历史 token 的 K 和 V 在新 token 到来时并不会改变。这正是 KV Cache 的基础。

## 第 7 页

注意力的后半部分调用 scaled dot product attention，难点在掩码。设 L 是键的长度，等于已缓存长度加上本次输入的 T。第一种情形，T 等于 L，说明没有缓存，直接用普通因果掩码；第二种，T 等于 1，只有一个新 token，它本来就在最后，能看到全部缓存，不需要掩码；第三种，多个新 token 接在缓存后面，is causal 会把掩码对齐到左上角，是错的，所以代码用下三角矩阵，并把对角线偏移 L 减 T，让每个新 token 只看到自己和之前的位置。最后把多头拼回去，再经 c proj 输出。

## 第 8 页

每个块的第二个子层是 MLP：c fc 先把维度升到 4 倍，经过 tanh 近似的 GELU 激活，再由 c proj 降回原来的维度。所有块走完之后，经过最终的层归一化 ln f，再由 lm head 把每个位置映射成词表大小的 logits。这里有个细节：代码让 wte 和 lm head 共用同一个权重矩阵，输入查表和输出打分用的是同一份参数，这就是权重共享。

## 第 9 页

有了 logits，就要决定下一个 token。generate 每一轮只取最后一个位置的 logits。如果 temperature 等于 0，就做贪心解码，直接取分数最高的那个；否则先把 logits 除以温度，温度越低，分布越尖锐。如果设置了 top k，就把第 k 大之外的分数全部设成负无穷，只在前 k 个候选里选。接着用 softmax 得到概率，再用 multinomial 随机抽出一个 token，拼回 idx，进入下一轮。

## 第 10 页

先看不用缓存时的代价。在 generate 里，如果关闭缓存，每一轮都会把整段已有序列，最多最后 1024 个 token，重新送进模型，经过每一层，重新计算所有旧 token 的查询、键和值。可是这一轮真正用到的，只有最后一个位置的 logits。右边的阶梯图里，每一行是一步，灰色是重复计算的旧 token，青色才是这一步真正需要的新位置。第一步算 1 个，第二步算 2 个，以此类推。生成 N 个 token，总共要做 1 加 2 一直加到 N 次 token 前向，约等于 N 平方除以 2，也就是 N 平方量级。这和源码里 KVCache 文档字符串的说法一致。以 N 等于 6 为例，共 21 次前向，只有 6 次是有用的。序列越长，浪费越严重：N 翻一倍，总计算量大约翻四倍。而且这些重复计算发生在每一层、每一个注意力头和每一个 MLP 里，层数越多，白白浪费的算力也就越多。

## 第 11 页

KV Cache 的出发点，是一个简单的观察。在因果掩码下，某个位置在每一层的键 K 和值 V，只取决于它自己以及更早的 token，后面来的新 token 不会改变它们。所以，旧 token 的 K、V 一旦算出来，就可以一直复用。新 token 要做的，只是用自己的查询 q，去和所有历史的 K、V 做注意力，再加上它自己新算出的那一份 k 和 v。换句话说，每一步我们只需要为新 token 算一次 q、k、v，然后把新的 k、v 追加到缓存末尾。那为什么不缓存查询 Q 呢？因为每一步只用最新 token 的 query，旧的 query 再也用不到。这和前面的代码完全对应：此时注意力的输入长度 T 等于 1，正是掩码的第二种情形，单个新 token 本来就排在最后，无需掩码；而位置编号从 kv cache 的 length 开始续接，保证新 token 拿到正确的位置嵌入。

## 第 12 页

打开缓存后，generate 会先创建一个 KVCache，最大长度是提示长度加最大生成数，但不超过 block size。之后，循环里始终是同一行代码：把 idx 从 kv cache 的 length 开始往后切出来，连同缓存一起送进模型。也就是说，只送缓存里还没有的 token。第一轮，缓存长度为 0，整段提示一次性送入，这叫预填充。此时 T 等于 L，用普通因果掩码，每一层的 K、V 被一次填满。这是一次较大的并行计算，但只发生一次。从第二轮开始，缓存里已经有了前面所有位置，只剩最新生成的那 1 个 token，这叫逐步解码。此时 T 等于 1，位置从 kv cache 的 length 续接，注意力读取全部 L 个缓存的键和值。每一步，只有一个新 token 穿过各层，这就是加速的来源。对比一下：不用缓存时，每一步送进模型的是整段序列；用缓存后，除了第一轮，每一步送进去的都只有 1 个 token，而结果完全一样。

## 第 13 页

来看代码怎么实现。LayerKVCache 负责一层的缓存。它的 k 和 v 一开始是空的，直到第一次调用 update 时，才按当前激活的批大小、头数、每头维度，以及数据类型和设备，一次性分配形状为 B、头数、max len、每头维度的缓冲区，之后就不用反复申请内存。每次 update 收到新的 T 个位置，就把它们写入 length 到 end 这一段，把 length 前移到 end，然后返回前 end 个位置的全部键和值。代码还会检查越界和形状是否一致，避免静默出错。KVCache 则为每一层各建一个 LayerKVCache，length 和 max len 取自第 0 层。在因果自注意力里，算出新 token 的 k、v 之后调用 update，拿到包含历史的完整 K、V，再与查询做注意力。整个过程里，旧 token 的 K、V 只写入一次，之后每一步都是直接读取，不再重新计算。

## 第 14 页

把加速量化一下。以生成 N 个 token 计，不用缓存时，第 k 步要前向 k 个 token，总共约 N 平方除以 2 次；用缓存后，提示只前向一次，之后每步只前向 1 个 token，总量是线性的。按我们的推导，N 等于 1024 时，前者是 52 万 4800 次，后者只有约 1024 次，相差五百多倍。要注意，注意力每步仍需读取全部 L 个缓存的键和值，这部分随长度线性增长；但 c attn、MLP 这些最重的矩阵乘法，不再对旧 token 重复。代价是显存：缓存的元素个数，是 2 乘层数、乘批大小、乘 max len、再乘 n embd。缓冲区的数据类型跟随模型激活。以 gpt2 小模型、批大小 1、长度 1024、float32 计算，大约是 72 MiB；换成 float16，就减半。这就是用显存换计算。对推理来说，这笔交易非常划算：几十兆的显存，换来的是从平方量级到线性量级的计算量下降。

## 第 15 页

最后看一个边界情况。GPT-2 使用学习得到的绝对位置嵌入 wpe，它只有 1024 行，所以上下文最长 1024。generate 创建缓存时，max len 取提示长度加最大生成数，与 block size 中的较小值。循环中，一旦 idx 的长度超过 max len，代码就丢掉缓存，之后每一步都退回无缓存模式，只取最后 1024 个 token 整段重算。为什么不能接着用缓存？因为裁剪掉最早的 token 之后，剩下每个 token 的位置编号都会前移，而缓存里的 K、V 是用旧位置算出来的，全部作废。右下角的示意图就展示了这种位置移位。

## 第 16 页

最后做个总结。第一，GPT-2 推理是一个自回归循环，每轮前向只产出一个新 token，再拼回输入继续。第二，模型主体是 n layer 个 Pre-LN 的 Transformer 块，靠残差连接逐层累加。第三，不用缓存时，每一步都要把整个前缀重算一遍，总共是 N 平方量级的 token 前向。第四，因果掩码保证历史 token 的 K、V 不会改变，所以可以缓存下来，之后每步只算新 token，总计算量降到线性量级。第五，代价是显存，它随 max len 线性增长；而上下文一旦超过 block size，就只能放弃缓存、裁剪后重算。完整代码都在 learn-gpt2 仓库的 gpt2.py 里，欢迎对照阅读。
