# 从注意力到大语言模型

这份综述把三篇论文按一条线读完：2017 年的 *Attention Is All You Need* 用注意力换掉循环网络，并在解码器里放上因果掩码；2019 年的 GPT-2 只保留这个解码器，用下一词预测在大规模网页文本上做零样本多任务；2020 年的 GPT-3 几乎不改配方，把模型放大到 1750 亿参数，使上下文里的几个例子成为一种新的使用方式。中间用本仓库 `src/learn_gpt2/gpt2.py` 把因果自注意力和 KV Cache 落到可以逐行对照的代码上。

面向的读者是想入门大语言模型、已经具备基本线代和 Python 的人。公式都配有“它在干什么”的说法。文中的 4 个词示例是教学构造，数值由同目录的 `demo.py` 用固定的 Q、K、V 算出；论文实验数字则保留原来的指标、数据划分和提示条件。

## 1. 问题从预测下一个词开始

语言模型估计的是一段文本的概率。自回归写法把联合概率拆成条件概率的连乘：

$$
P(x_1, \ldots, x_T) = \prod_{t=1}^{T} P(x_t \mid x_1, \ldots, x_{t-1})
$$

每一个因子都是“给定已经看到的词，下一个词是什么”。句子“今天天气真好”因此变成四次预测：看到“今天”预测“天气”，看到“今天天气”预测“真”，以此类推。训练时把输入和标签错开一位，整句可以一次送进网络，这叫 teacher forcing。生成时右边还是空的，只能把刚采样出来的词接回去，再预测下一个。后面所有关于掩码和缓存的讨论，都是在保证这两件事算的是同一个条件分布，并且不要把已经算过的过去反复重算。

循环网络天然符合这个从左到右的顺序，但有两个代价。信息从句首走到句尾，路径长度是序列长度 \(n\)，远距离依赖要穿过很多步。同时，第 \(t\) 步必须等第 \(t-1\) 步算完，没法按位置并行。卷积可以并行，一层却只能看一个局部窗口；要把路径缩短到常数，就要堆很多层，或者把卷积核放大到和句子一样长。

Vaswani 等人用一张表把这笔账写清楚（论文表 1）。自注意力每层的计算是 \(O(n^2 \cdot d)\)，必须串行的步数是 \(O(1)\)，任意两个位置之间的路径长度也是 \(O(1)\)。循环层是 \(O(n \cdot d^2)\) 的计算、\(O(n)\) 的串行和 \(O(n)\) 的路径。\(n\) 小于表示维度 \(d\) 时，自注意力往往比循环层更便宜，同时还换来了全句一步可达。代价是序列一长，平方项就会主导。后面的 KV Cache 并没有取消这个平方，它取消的是“每生成一个词就把过去重新算一遍”。

## 2. Transformer 做了什么

*Attention Is All You Need*（Vaswani et al., 2017）把机器翻译的编码器和解码器都改成“注意力 + 逐位置前馈网络”的堆叠，不再用循环或卷积当主干。Base 模型 6 层，模型宽度 \(d_{\text{model}} = 512\)，前馈层宽度 2048，8 个头，每个头的键和值维度都是 64，大约 6500 万参数。Big 模型加宽到 1024、16 个头、前馈层 4096，大约 2.13 亿参数。

### 2.1 缩放点积注意力

每个位置准备三份向量。Query 是“我在找什么”，Key 是“我拿什么被匹配”，Value 是“我真正交出去的内容”。相似度用点积，再除以 \(\sqrt{d_k}\)，然后按行做 softmax，得到一组和为 1 的权重，最后对 Value 加权求和：

$$
\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{QK^{\mathsf T}}{\sqrt{d_k}}\right) V
$$

除以 \(\sqrt{d_k}\) 不是装饰。如果 Query 和 Key 的每个分量均值是 0、方差是 1，点积的方差就是 \(d_k\)。维度一大，点积的绝对值就大，softmax 进入饱和区，梯度几乎消失。除以 \(\sqrt{d_k}\) 把这个方差拉回 1 附近。

多头是把同一组 512 维切成 8 个 64 维的小注意力，各自匹配，再拼回去做一次线性变换。不同的头可以关心不同的关系。表 3 的消融在总计算量大致不变时改头数：只有 1 个头，比最好的设置大约低 0.9 个 BLEU；头太多、每一头太窄，也会变差。这里的 BLEU 是英德开发集 newstest2013，不是后面的测试集。

### 2.2 三种注意力

编码器的自注意力允许每个源词看整个源句。解码器里有两种注意力。一种的 Query 来自解码器、Key 和 Value 来自编码器，翻译时这是在查阅原文。另一种是解码器自己的自注意力，必须遮住未来：位置 \(i\) 不能看位置 \(i\) 之后的词。论文 3.2.3 节写的是，这个掩码再叠加“输出嵌入比标签错开一位”，位置 \(i\) 的预测就只依赖已经知道的输出。掩码加在 softmax 之前，被挡住的位置最终权重是 0。

每个子层外面是残差连接和 LayerNorm。前馈网络对每个位置独立作用，原始论文用 ReLU：

$$
\mathrm{FFN}(x) = \max(0, xW_1 + b_1) W_2 + b_2
$$

Base 的中间宽度是 2048，等于 4 倍模型宽度。层与层不共享这组参数。注意力本身不分先后，所以输入端还要加上位置编码。论文用正弦和余弦；表 3 的 E 行换成可学习的位置嵌入，开发集 BLEU 从 25.8 变成 25.7，几乎一样。GPT 后来选择的就是这种可学习的绝对位置表。

### 2.3 训练和翻译结果

优化器是 Adam。学习率先用 4000 步线性升温，再按步数平方根的倒数下降。正则有两处：子层输出、以及嵌入与位置编码之和，都做 dropout，Base 的比率是 0.1；标签平滑 \(\epsilon = 0.1\)，它会让困惑度变差，但 BLEU 变好。

WMT 2014 英译德，Big 模型在 newstest2014 上是 28.4 BLEU，比当时包括模型集成在内的最好结果高出两个 BLEU 以上，8 张 P100 训练了 3.5 天。Base 是 27.3，大约 12 小时。英译法要分清出处：摘要和表 2 写的是 41.8，正文 6.1 节写的是 41.0。两个数字都在同一份 PDF 里。Big 做英法时 dropout 用的是 0.1，不是表 3 里为 Big 列出的 0.3。解码是束宽 4、长度惩罚 0.6，并对最后若干个检查点取平均。

这件事的重要性不在某一个 BLEU 数字，而在于：序列模型的主干可以不再是循环。路径变短、训练可以按位置并行，后面的语言模型才有条件往大里长。

## 3. 因果自注意力

解码器里的那块掩码，就是后来 GPT 系列唯一保留的注意力。它有三个互相支撑的理由。

生成是从左到右的。写到第 \(t\) 个词时，右边还不存在，模型不能在训练里养成偷看右边的习惯。训练时标签就是右边那个词，如果允许看未来，网络可以直接抄答案，损失变成 0，什么也学不到。最后，只要每个位置的计算不依赖未来，旧位置的 Key 和 Value 就不会因为新词改变，缓存才是正确的。

### 3.1 掩码的形状

设序列长度为 \(T\)。分数矩阵是 \(T \times T\)：第 \(i\) 行是第 \(i\) 个 Query，第 \(j\) 列是第 \(j\) 个 Key。因果掩码是包含对角线的下三角。\(j > i\) 的位置在 softmax 之前填成 \(-\infty\)；\(j \le i\) 保留，包括 \(j = i\)。对角线要留下，因为当前位置可以读自己的表示。它要预测的是下一个词，不是把自己遮掉。

softmax 对 \(-\infty\) 的行为很干净。先减去行内最大值再取指数时，\(-\infty\) 变成 0，其余位置重新归一化，所以每一行的权重仍然和为 1。被挡住的未来不会分走任何概率。

### 3.2 一个算完的例子

`demo.py` 用四个词“今天、天气、真、好”，一个头，\(d_k = 4\)，所以缩放因子是 2。Q 和 K 是固定的教学向量，不是训练出来的权重。掩码之后的注意力权重，保留两位小数，是：

| Query \ Key | 今天 | 天气 | 真 | 好 |
| --- | --- | --- | --- | --- |
| 今天 | 1.00 | 0 | 0 | 0 |
| 天气 | 0.41 | 0.59 | 0 | 0 |
| 真 | 0.22 | 0.33 | 0.45 | 0 |
| 好 | 0.16 | 0.18 | 0.29 | 0.38 |

以“真”这一行为例，缩放后的分数大约是 0.14、0.57、0.87 和 \(-\infty\)。指数再归一化，得到 0.22、0.33、0.45 和 0，和为 1。把最后一个词的 Key 和 Value 改成完全不同的数，前三个位置的输出最大绝对误差是 0。未来进不来，这不是近似，是掩码本身的结构。

训练时四个位置一起算，并行的是矩阵乘法，信息依赖仍然是这张下三角。生成时未来真的未知，所以一次只追加一个词。两种调度对旧位置给出同一个结果，缓存才能在生成时复用训练时那种“旧行不再变化”的性质。

### 3.3 对照 gpt2.py

`CausalSelfAttention` 在 `gpt2.py` 第 92 到 122 行。以 GPT-2 small 为例，宽度 \(C = 768\)。`c_attn` 是一个从 768 到 \(3 \times 768\) 的线性层，一次投影出 q、k、v，再切成 12 个头，每头 \(h_s = 64\)。形状从 \((B, T, C)\) 变成 \((B, n_h, T, h_s)\)。

打分、缩放、掩码和加权都交给 `F.scaled_dot_product_attention`。不传 `scale` 时，默认除以 \(\sqrt{h_s}\)。这里 \(\sqrt{64} = 8\)。多头拼回 \((B, T, C)\) 之后，`c_proj` 再做一次 768 到 768 的线性变换，把各个头混合起来。这一层注意力的参数，含 bias，大约是 236 万；12 层合计大约 2835 万。MLP 另算，它不在 token 之间交换信息。Block 里 token 之间唯一的通道就是这块注意力。

有缓存之后，Query 的长度 \(T\) 和 Key 的长度 \(L\) 不一定相等。第 110 到 120 行因此分三种掩码：

- \(T = L\)：没有更早的缓存，用 `is_causal=True`。掩码贴着左上角。
- \(T = 1\)：解码一步。这一个新 Query 可以看全部已缓存的 Key，不必再遮。
- 其他情况：一次来了多个新词，前面又已经有缓存。第 \(i\) 个新 Query 的绝对位置是 \(L - T + i\)，掩码用 `tril`，对角线偏移 \(L - T\)，贴住右下角。此时如果误用 `is_causal=True`，掩码会贴在左上角，把本该看见的缓存挡住。代码注释写了这件事。

举一个具体的第三种情况：\(T = 2\)、\(L = 5\)。两个新 Query 坐在绝对位置 3 和 4（从 0 数）。第一行只能看到前 4 个 Key，第二行可以看到全部 5 个。

## 4. KV Cache

`KVCache` 和 `LayerKVCache` 在第 35 到 89 行。类的文档字符串把动机说得很直接：没有缓存时，每一步都把整个前缀重算一遍，生成 \(N\) 个词要做 \(O(N^2)\) 次 token 前向；有缓存时，每一步只把最新的 token 送进网络，再用它的 Query 去看已经存好的 Key 和 Value。

### 4.1 预填充，再解码一步

提示词先做一次 prefill，每一层把 K、V 写进缓存。之后每个新 token 只计算自己的 q、k、v，`update` 把 k、v 追加到 `length` 之后，并返回从 0 到新长度的全部历史。位置编号不能从 0 重新数。`forward` 里，有缓存时位置下标从 `kv_cache.length` 开始，因为学来的绝对位置表认的是这个绝对位置。

用上面四个词做预填充，缓存长度为 4。再来一个新 token，Query 只有 1 行，Key 和 Value 有 5 行。这一行应当等于把五个词重算一遍、取因果矩阵的最后一行。`demo.py` 里两条路径的最大绝对误差约 \(5.6 \times 10^{-17}\)，是浮点误差。缓存改变计算路径，不改变数学结果。

### 4.2 形状和显存

每一层存 K 和 V 两份。单份的形状是 \((B, n_h, L, h_s)\)。因为 \(n_h \times h_s = C\)，字节数可以收成：

$$
\text{字节} = n_{\text{layer}} \times 2 \times B \times L \times C \times \text{每元素字节}
$$

GPT-2 small、batch 为 1、长度 1024、fp16：\(12 \times 2 \times 1024 \times 768 \times 2 = 36\) MiB。GPT-3 175B 的层数和宽度按论文表 2.1 是 96 层、宽度 12288，长度 2048、fp16、batch 为 1，正好是 9 GiB。batch 乘到 64，仅缓存就是 576 GiB，这还不算 1750 亿个参数本身。缓存省的是计算，付的是随 batch 和上下文线性增长的显存。

### 4.3 有缓存和没缓存，差在哪里

从空上下文生成到长度 \(N = 1024\)，只看一个头要算的分数个数：

| 做法 | 分数个数 | 相对有缓存 |
| --- | --- | --- |
| 每步重算整张 \(L \times L\) 方阵 | 358,438,400 | 683 倍 |
| 每步只算下三角 | 179,481,600 | 342 倍 |
| 有 KV Cache，每步只有 \(1 \times L\) | 524,800 | 1 倍 |

token 前向次数是另一笔账。没有缓存时，各步长度之和是 \(1 + 2 + \cdots + 1024 = 524800\)。有缓存时是 1024。大约少 512 倍。投影更是如此：没有缓存时，每一步都要把整段的 Q、K、V 重新投影一遍。

这里最容易说错的一句是“有了缓存，注意力就变成线性的”。生成完 \(N\) 个词，注意力分数的总数仍是 \(\sum_{L=1}^{N} L = O(N^2)\)，因为每一个新词还是要看全部历史。没有缓存时，如果每步都重算整张方阵，总数是 \(O(N^3)\)。缓存把 \(O(N^3 d)\) 的重复注意力降到 \(O(N^2 d)\)，把重复的投影从 \(O(N^2 d^2)\) 降到 \(O(N d^2)\)。历史本身还在。

因果掩码是这件事的前提。如果旧位置可以看未来，新词一到，旧的 Key、Value 和旧行的输出都会变，缓存立刻作废。掩码把依赖限制在过去和自己，旧的 K、V 才是常量。GPT-2 的位置表只有 1024 项。序列一旦超过 `block_size`，裁剪后的窗口和缓存里的绝对位置对不上，`generate` 会放弃缓存、退回重算。这是正确性边界，不是实现细节。

## 5. GPT-2：不更新参数的多任务

Radford 等人 2019 年的论文标题是 *Language Models are Unsupervised Multitask Learners*。模型只做下一词预测，不为翻译、问答或摘要单独准备损失。任务靠文本本身说出来：给一段上下文，让模型把下文接完。他们把这叫做零样本。需要把口径说清楚：零样本指的是下游任务上没有梯度更新。提示仍然在指定要做什么，个别评测还会加停用词过滤。这还不是 GPT-3 后来形式化的 few-shot：把十几个输入输出例子塞进上下文。

### 5.1 WebText 和字节级 BPE

训练数据叫 WebText。他们抓取 Reddit 上至少 3 个 karma 的外链，把这种点赞当作便宜的人工质量过滤，一共约 4500 万条链接。去重和清洗之后，略多于 800 万篇文档、40 GB 文本，并且不包含 2017 年 12 月之后创建的链接。维基百科被整份拿掉，因为太多下游测试集都来自那里。

分词用字节级 BPE，词表 50257。底表只有 256 个字节，所以任意 Unicode 字符串都有概率，没有传统意义上的未知词。他们禁止 BPE 跨字符类别合并，避免把 dog、dog!、dog? 占成许多几乎重复的词，空格是例外。上下文从 GPT 的 512 加到 1024，batch size 论文写的是 512。

### 5.2 相对原始 Transformer 的改动

论文 2.3 节写得很具体，模型大体跟随 GPT，并做了几处修改。LayerNorm 挪到每个子层的输入，类似预激活残差网络，全部子层之后再加一次 LayerNorm。这就是 Pre-LN。本仓库的 Block 是：

```text
x = x + attn(ln_1(x))
x = x + mlp(ln_2(x))
```

堆叠结束还有一次 `ln_f`。残差路径上的投影，初始化时按 \(1/\sqrt{N}\) 缩小，用来抵消一层层相加带来的方差积累。论文说 \(N\) 是残差层的数量。本仓库把每个 Block 里注意力和 MLP 两次残差都算进去，所以标准差是 \(0.02 / \sqrt{2 \cdot n_{\text{layer}}}\)，并且只缩放名字以 `c_proj.weight` 结尾的参数。位置编码是可学习的绝对位置嵌入 `wpe`，不是正弦函数。激活沿用 GPT 的 GELU；本仓库 MLP 用的是 tanh 近似，和 Hugging Face 的 GPT-2 一致。

四个尺寸在论文表 2 里是：

| 论文参数量 | 层数 | 宽度 | 公开配置的头数 |
| --- | --- | --- | --- |
| 117M | 12 | 768 | 12 |
| 345M | 24 | 1024 | 16 |
| 762M | 36 | 1280 | 20 |
| 1542M | 48 | 1600 | 25 |

论文表 2 没有单列头数。头数来自公开的 GPT-2 配置，也是本仓库 `GPT2_CONFIGS`。同一张表的最小模型，若把词嵌入和 bias 按可训练参数重算，大约是 1.24 亿。本仓库注释用的是后一种口径。层数和宽度以论文为准。四个模型当时都还没有拟合完 WebText，留出集上的困惑度仍会随着多训练而下降。

### 5.3 实验，以及这些数字的条件

零样本语言建模上，8 个数据集里有 7 个超过当时的最好结果。例外是 One Billion Word：1542M 的困惑度是 42.16，此前最好是 21.8。那个数据集把句子打乱了，长距离结构被拆掉，大上下文帮不上忙。

LAMBADA 要预测那些至少需要约 50 个词的上下文、人才能猜中的句末单词。困惑度从 99.8 降到 8.6，表 3 里 1542M 的数字是 8.63。准确率从 19% 提高到 52.66%。论文检查错误后发现，很多预测是合法的续写，只是没有停在句末。再加上停用词过滤，近似“答案必须是句末”这个约束，准确率到 63.24%，比此前在不同限制条件下的最好结果再高约 4 个百分点。读这个数字时，过滤条件要一起读。

儿童书测试因为《丛林之书》出现在 WebText 里，论文改报没有明显重叠的验证集：普通名词 93.3%，命名实体 89.1%。Winograd Schema 达到 70.70%，比此前最好高 7 个百分点，但只有 273 道题。这些结果都没有做任务微调。

## 6. GPT-3：上下文里的少样本

Brown 等人 2020 年的论文标题换成 *Language Models are Few-Shot Learners*。他们仍然不在测试时更新参数，但把“给模型看几个例子”这件事系统化了，并称之为 in-context learning，上下文学习。图 1 的意思是：模型越大，同样多的上下文例子带来的收益越陡。

### 6.1 四种用法

论文第 2 节把用法分成四档。前三档只有前向计算：

- Zero-shot：只有一段自然语言任务说明，没有输入输出示范。
- One-shot：说明之外再给一个完整例子。
- Few-shot：例子尽量多，通常 10 到 100 个，直到塞满 2048 的上下文。
- Fine-tuning：用任务数据更新权重。这篇论文把它当作对照，不是主角。

Few-shot 往往更强。论文也写明，如果要和人比较，one-shot 甚至 zero-shot 有时才是更公平的设置，因为人通常不需要先看一百个例子才知道一道题在问什么。

### 6.2 规模、架构和数据

8 个模型从 1.25 亿到 1750 亿，每个都训练 3000 亿个 token，上下文都是 2048。被叫做 GPT-3 的那个是 175B：96 层，宽度 12288，96 个头，每头 128 维，batch 约 320 万 token，学习率 \(0.6 \times 10^{-4}\)。前馈层仍然是 4 倍宽度。架构沿用 GPT-2 的 Pre-LN、初始化缩放和可逆分词，另外隔层使用稠密注意力和局部带状稀疏注意力，类似 Sparse Transformer。

数据不是按体积抽样。表 2.2 的混合是：

| 数据 | 规模 | 训练混合中的权重 | 训练 300B token 时看过的遍数 |
| --- | --- | --- | --- |
| 过滤后的 Common Crawl | 4100 亿 | 60% | 0.44 |
| WebText2 | 190 亿 | 22% | 2.9 |
| Books1 | 120 亿 | 8% | 1.9 |
| Books2 | 550 亿 | 8% | 0.43 |
| 英文 Wikipedia | 30 亿 | 3% | 3.4 |

高质量来源被重复看，Common Crawl 和 Books2 看不满一遍。他们试图去掉与下游测试集重叠的文档，但过滤有一个已知的 bug，因为训练成本太高而没有重训。第 4 节专门估计了残留重叠的影响。

### 6.3 实验里能看见的模式

几个数字足够看出 few-shot 和规模各自起什么作用。都是 175B，除非另加说明。

| 任务 | Zero-shot | One-shot | Few-shot |
| --- | --- | --- | --- |
| LAMBADA 准确率 | 76.2% | 72.5% | 86.4% |
| LAMBADA 困惑度 | 3.00 | 3.35 | 1.92 |
| TriviaQA | 64.3% | 68.0% | 71.2% |
| CoQA，F1 | 81.5 | 84.0 | 85.0 |
| 两位数加法 | 76.9% | 99.6% | 100% |

LAMBADA 的 one-shot 低于 zero-shot，因为他们在 one-shot 和 few-shot 里改用了填空格式。这种格式需要好几个例子，模型才认得“只要一个词”。Few-shot 因此从 zero-shot 的 76.2% 升到 86.4%，比此前 68% 的最好结果高约 18 个百分点。TriviaQA 的 few-shot 71.2% 超过了表中列出的闭卷微调结果。CoQA 的 85.0 接近人类和微调模型，但不是每一项阅读理解都这样：QuAC 明显更弱。

算术把“规模”和“例子”分开得更清楚。两位数加法在 few-shot 下是 100%，三位数加法是 80.4%，五位数加法只剩 9.3%。13B 模型做两位数加减，也只有大约一半的时候做对。论文在训练集里检索了这些算式，3 位数加法只命中 0.8%，而且错误常常像是忘了进位，说明不全是背下来的。新闻生成用了三篇示范：大约 200 词的文章，人类判断 175B 是否为机器所写的准确率是 52%，95% 区间 49% 到 54%，接近随机；故意做差的对照模型则是 86%。

SuperGLUE 的 few-shot 平均分是 71.8，每个任务 32 个例子，高于表中 BERT-Large 微调的 69.0，仍明显低于微调最高水平 89.0。WiC 是 49.4%，几乎等于随机。比较两个句子里一个词是否同义，正是自回归模型不方便做的事。

### 6.4 论文自己写下的限制

第 5 节没有把这些限制藏起来。长文本仍然会语义重复、自相矛盾，或者出现不承接的句子；论文放出了 500 段未挑选的无条件样本。常识物理的某些问法仍然弱。比较类任务，例如 WiC 和 ANLI，以及一部分需要来回对照的阅读理解，few-shot 接近机会水平。作者把这和“没有双向信息”联系起来：模型不方便同时看两段话再做一个短判断。

更根本的限制有四条。预训练目标对每个 token 一视同仁，并不知道哪一个词更值得预测。测试时可以 one-shot，训练时看过的文本远多于一个人的一生，样本效率仍然差。模型不接地，没有视觉和身体经验。175B 的推理很贵，论文把蒸馏列成可能的出路，但当时还没有在这个规模上做过。

Few-shot 到底是在推理时学会一个新任务，还是在认出训练时见过的任务格式，论文认为仍不清楚，而且不同任务的答案可能不同。造词、字母重排更像临时学会的；翻译显然主要来自预训练。此外，预测不一定校准，数据里的刻板印象会被复述，生成文本也更难被人认出来，滥用的风险因此变大。这些是第 5 节和第 6 节的内容，不是后来的读者追加的批评。

## 7. 三条线怎么接上

Transformer 证明注意力可以当主干，并规定解码器不能看未来。GPT-2 扔掉编码器，把这个因果解码器放在 WebText 上，用 Pre-LN 和按深度缩小的初始化把深层残差稳住，然后发现不更新参数也能做多种任务。GPT-3 保留这套配方，把深度、宽度和数据一起放大，于是上下文中的例子从“偶尔有用”变成“随规模越来越有用”。

因果自注意力是这条链的数学约束：每一行只依赖自己和过去，权重和为 1。KV Cache 是同一条约束的工程后果：旧的 K、V 是常量，新词只算自己的一行。本仓库把这两件事写在 `gpt2.py` 里。读 `forward` 和 `generate` 时，可以对着第 3 节的下三角和第 4 节的 683 倍，看代码在哪一种 \(T\) 和 \(L\) 的关系下选择掩码，以及什么时候必须放弃缓存。
