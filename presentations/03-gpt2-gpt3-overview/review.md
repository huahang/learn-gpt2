# 从注意力机制到 GPT-2 与 GPT-3

## 摘要

2017 年的 Transformer、2019 年的 GPT-2 和 2020 年的 GPT-3，可以沿着一条清楚的线索阅读：先解决序列中的信息怎样交换，再研究大量文本训练能学到哪些可迁移能力，最后检验扩大模型后能否通过上下文示例直接完成任务。三篇论文分别推进了**网络结构、任务迁移方式和规模化评估**。它们并不是三个互不相关的模型，也没有把“预测下一个词”依次换成三种不同的学习目标。

本文面向了解基本向量与概率、尚未系统学习大语言模型的读者。先用原创手算例子解释注意力，再连接完整 Transformer、GPT-2 的自回归语言建模、GPT-3 的上下文学习。实验数字均保留数据集、指标和评估设置；“会生成”“能迁移”“理解可靠”之间的区别贯穿全文。GPT-2 与 GPT-3 讨论的是当时的基础语言模型，不能直接等同于经过后续指令训练的人机对话产品。

三篇原文分别记作 [T]、[G2]、[G3]。方括号后的章节与表号用于回到原文核查，文末给出可点击链接。本文中的中文情境、手算数据、伪代码和比较解释为教学构造，不是论文中实测的注意力或模型输出。

## 1 三篇论文分别在回答什么问题

| 论文 | 核心问题 | 主要改变 | 主要证据 |
|---|---|---|---|
| [T] Attention Is All You Need | 不依赖循环和卷积，能否高效建模序列依赖？ | 以注意力为核心的编码器—解码器 Transformer | 机器翻译、结构消融和句法分析 |
| [G2] Language Models are Unsupervised Multitask Learners | 只在广泛文本上训练语言模型，能否直接迁移到多种任务？ | WebText、扩大模型、以文本格式诱导任务 | 跨领域语言建模、阅读理解、翻译、摘要等 |
| [G3] Language Models are Few-Shot Learners | 扩大语言模型后，能否只给少量示例就完成任务？ | 规模扩展、混合语料、系统比较 zero/one/few-shot | 多任务评估、规模曲线、上下文示例数量实验 |

理解这条路线需要区分三个对象。**架构**规定信息怎么流动；**训练目标**规定哪些预测会获得奖励或受到惩罚；**使用方式**规定测试时提供什么信息、是否更新参数。Transformer 是架构，下一 token 预测是目标，few-shot prompting 是使用方式。把这三层分开，许多看似矛盾的说法就能同时成立：同一种架构可以用于翻译或语言建模，同一个预训练模型可以接受不同任务提示，而不需要为每个提示重新训练。

## 2 从“查找相关信息”理解注意力

### 2.1 为什么一个固定向量不够方便

设一句话是“老师把书递给学生，因为他马上要开始阅读”。理解“他”需要考虑前面的角色、动作和语境；仅看相邻词通常不够。循环网络可以逐步传递信息，但远处线索要经过多个时间步。注意力提供另一条路线：在当前需要产生表示的位置，对可见位置逐一计算相关程度，再把它们提供的信息按比例汇总。

可以用“带模糊匹配的资料检索”类比这个过程：当前需求是查询，候选资料有检索标签和实际内容。不过，这里的标签与内容通常不是人手编写的字段，而是模型从向量中学出来的表示。相关程度也不等同于人类判断的语义相似度；一个位置可能需要寻找否定词、句法依赖或复制对象。

注意力并非 2017 年才出现。[T] 的贡献是把自注意力、多头机制、位置表示和前馈子层组织成能够独立承担序列转换的架构，并用实验说明这条路线的效果与训练效率。[T，§1–§3]

### 2.2 Query、Key、Value 是什么

把长度为 $n$ 的输入表示写成矩阵 $X\in\mathbb R^{n\times d_{model}}$。每一行是一个 token 在当前层的表示。一个自注意力头通过三组可训练矩阵得到：

$$
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V.
$$

- **Query，查询 $q_i$**：第 $i$ 个位置需要什么信息。
- **Key，键 $k_j$**：第 $j$ 个位置以什么特征供别人匹配。
- **Value，值 $v_j$**：第 $j$ 个位置真正贡献到输出中的内容。

Q 与 K 决定“如何分配权重”，V 决定“汇总什么内容”。三者分开，使模型不必把用于检索的表示和用于传递的表示强行设为相同。自注意力的三者来自同一个序列，但三组投影通常不同，所以 Q、K、V 也通常不同。

对第 $i$ 行，完整计算是：

$$
s_{ij}=\frac{q_i k_j^{\mathsf T}}{\sqrt{d_k}}+M_{ij},\quad
\alpha_{ij}=\frac{e^{s_{ij}}}{\sum_{r}e^{s_{ir}}},\quad
z_i=\sum_j\alpha_{ij}v_j.
$$

矩阵形式为：

$$
\operatorname{Attention}(Q,K,V)
=\operatorname{softmax}\!\left(\frac{QK^{\mathsf T}}{\sqrt{d_k}}+M\right)V.
$$

若 Q 和 K 分别有 $n_q$、$n_k$ 行，那么得分矩阵是 $n_q\times n_k$，softmax 沿每一行的“候选 key”维度计算，输出是 $n_q\times d_v$。自注意力时两种长度相同；交叉注意力时不必相同。[T，§3.2，式 1]

### 2.3 一个可以按计算器复现的例子

以下数值专为说明步骤而构造。设只有一个查询，且 $d_k=2$：

$$
q=(1,0),\quad
K=\begin{bmatrix}1&0\\0&1\\1&1\end{bmatrix},\quad
V=\begin{bmatrix}1&0\\0&2\\2&1\end{bmatrix}.
$$

点积为 $(1,0,1)$，除以 $\sqrt2$ 后约为 $(0.707,0,0.707)$。取指数并归一化：

$$
\alpha\approx(0.401,0.198,0.401).
$$

于是：

$$
z\approx0.401(1,0)+0.198(0,2)+0.401(2,1)
=(1.203,0.797).
$$

这里没有“选中第一条就丢掉其他条”。输出混合了三个 value，而第一、第三个候选贡献更多。权重之和为 1，但输出向量的分量不需要加起来为 1。

如果这个查询位于序列第二个位置，第三个位置尚未发生，因果掩码应令第三个分数为负无穷。此时前两个分数重新归一化，权重约为 $(0.670,0.330,0)$，输出变成 $(0.670,0.660)$。**掩码放在 softmax 之前**，所以被屏蔽位置的概率为零，允许位置的概率重新分配；直接在 softmax 后把某项清零而不重新归一化，得到的不是同一个操作。

### 2.4 为什么要除以根号维度

假设 q、k 的各分量近似独立、均值为 0、方差为 1，那么 $q\cdot k$ 的方差随维度增长为 $d_k$。维度越大，未经缩放的点积越容易出现很大的正负值，softmax 可能过早接近只选一个位置，部分梯度变小。除以 $\sqrt{d_k}$ 使点积的典型尺度更稳定。[T，§3.2.1，脚注 4]

这是一种初始化与训练尺度上的解释，不是“所有训练阶段的向量都独立同分布”的断言。学习后向量会有相关性。实际实现还常在 softmax 前减去该行最大值，以避免指数溢出；减去同一个常数不会改变归一化后的结果。

### 2.5 多头机制为什么有用

一个加权平均容易把多种关系压在同一组权重里。多头注意力让若干组独立投影在不同子空间中汇总信息，再将结果拼接并线性组合：

$$
\operatorname{MultiHead}(X)=
\operatorname{Concat}(head_1,\ldots,head_h)W_O.
$$

[T] 的 base 模型中 $d_{model}=512$、$h=8$，每个头的 key/value 维度都是 64。总宽度被拆给不同头，因而不能简单说“8 个头就相当于完整计算量乘 8”。可以把各头类比为从不同角度读同一句话，但“某个头永远负责语法、另一个头永远负责事实”只是过度简化。头的分工来自训练，可能混合、冗余，也可能随层和输入变化。[T，§3.2.2；表 3]

### 2.6 三种注意力不要混淆

| 类型 | Query 来自哪里 | Key/Value 来自哪里 | 能看哪些位置 |
|---|---|---|---|
| 编码器自注意力 | 源序列 | 同一源序列 | 通常全部有效源位置 |
| 解码器因果自注意力 | 目标序列前缀 | 同一目标序列 | 当前位置与此前位置 |
| 编码器—解码器交叉注意力 | 解码器表示 | 编码器输出 | 通常全部有效源位置 |

因果掩码约束时间方向，padding 掩码排除为批处理补上的无效位置，两者用途不同。GPT-2 与 GPT-3 的基础架构只有因果自注意力，没有原始翻译 Transformer 的独立编码器与那套交叉注意力子层。

注意力权重可以帮助观察模型利用了哪些位置，但它本身不能证明因果解释。例如改动某个 token 会同时改变多个层里的 Q、K、V；仅看最后一层某张热图，无法排除这些间接路径。

### 2.7 因果自注意力逐步展开

**“因果”首先是一条信息可见性规则。** 在从左到右生成文本时，第 $i$ 个位置只能利用 $x_0,\ldots,x_i$。它不能利用 $x_{i+1}$ 等未来文本，否则训练时拿到的信息比真实生成时更多。这里的“因果”不表示模型掌握了现实世界的因果推理，它只规定序列中的信息流向。

为避免编号歧义，本节采用从 0 开始的索引。设有四个教学 token，暂时把“我、喜欢、学习、模型”各视为一个 token；真实分词结果须由分词器决定。输入矩阵的每一行分别是这些 token 的 embedding 加位置 embedding。每个位置都分别投影出自己的 q、k、v：

$$
q_i=x_iW_Q,\quad k_i=x_iW_K,\quad v_i=x_iW_V.
$$

整句一次矩阵乘法 $Q=XW_Q$ 只是将四次同类操作并行起来，并没有提前混合不同位置。投影参数在位置之间共享，位置向量不同，所以得到的 q、k、v 不同。较深层使用的是前一层产生的上下文化表示，公式中的 $x_i$ 此时不再是最初的词向量。

**得分矩阵的行是接收信息的位置，列是提供信息的位置。** 令 $S=QK^{\mathsf T}/\sqrt{d_k}$，则 $S_{ij}$ 回答“第 $i$ 个查询对第 $j$ 个键给多高匹配分数”。例如第 2 行第 0 列，表示“学习”这一位置向“我”这一位置读取信息的匹配程度。若把行列说反，热图与掩码解释都会反过来。

四个位置的允许连接矩阵为：

$$
A_{allowed}=\begin{array}{c|cccc}
 &k_0&k_1&k_2&k_3\\\hline
q_0&1&0&0&0\\
q_1&1&1&0&0\\
q_2&1&1&1&0\\
q_3&1&1&1&1
\end{array}
\qquad
M=\begin{bmatrix}
0&-\infty&-\infty&-\infty\\
0&0&-\infty&-\infty\\
0&0&0&-\infty\\
0&0&0&0
\end{bmatrix}.
$$

允许区域是**包含对角线的下三角**。包含对角线是因为位置 $i$ 已经知道当前 token $x_i$，正在预测的是下一个 token $x_{i+1}$。把对角线也遮住会改变模型定义，还会使第一个位置没有可见 key；若不另作处理，对全负无穷行做 softmax 会产生无效数值。

应用掩码后的 $α=\operatorname{softmax}(S+M)$ 仍是 $4\times4$ 矩阵。第 0 行只剩一个候选，权重一定为 $(1,0,0,0)$；第 1 行只在前两个 key 上归一化；第 2 行只在前三个 key 上归一化；第 3 行可以使用全部四个。每一个有效查询行的权重和是 1，而每一列没有“必须加起来为 1”的要求。通常不同位置对同一个词可以同时赋予很大权重。

例如手动指定某一行缩放后的分数为 $(2,1,0,3)$，假设它是第 1 行，屏蔽未来后变成 $(2,1,-\infty,-\infty)$。最终权重约为 $(0.731,0.269,0,0)$。虽然第四列原分数最高，它仍被完全禁止；掩码是硬约束，并不是希望模型训练后自行学会遵守的软偏好。

**右移标签使“当前位置可见”与“答案不可见”同时成立。** 假设完整训练片段有五个教学 token：“我、喜欢、学习、模型、。”。取前四个作输入，后四个作预测标签：

| 预测行 | 此行可用前缀 | 输入中的当前 token | 该行标签 |
|---:|---|---|---|
| 0 | 我 | 我 | 喜欢 |
| 1 | 我、喜欢 | 喜欢 | 学习 |
| 2 | 我、喜欢、学习 | 学习 | 模型 |
| 3 | 我、喜欢、学习、模型 | 模型 | 。 |

“学习”虽然出现在训练输入矩阵中，却位于第 2 列，被第 1 行的掩码屏蔽，所以第 1 行无法直接看到自己的标签。另一种等价实现是把完整序列送入模型，在损失计算时对 logits 与 labels 做移位；还可以用起始符号配合右移输入。关键是**预测位置和监督标签相差一步**，而不是记住某个库究竟在哪一行代码移动数组。

**多层叠加为什么仍然不会偷看未来？** 只遮住第一层并不够，每一层都必须遵守因果约束。可以作一个简单归纳：初始位置 $i$ 只有自己的 token 与位置；假设上一层第 $j$ 个表示只依赖 $x_{\le j}$，那么本层第 $i$ 行只读取 $j\le i$ 的 key/value，它们依赖的 token 都在 $x_{\le i}$ 内。逐位置的 FFN、LayerNorm 和残差也不会把未来位置混进来。于是最后任意一层的位置 $i$ 都只依赖前缀。这个逐层性质让 teacher forcing 能同时计算所有预测行，又不破坏自回归定义。

下面是单头概念伪代码，省略 batch、dropout 和输出投影：

```text
Q = X @ Wq                     # [T, dk]
K = X @ Wk                     # [T, dk]
V = X @ Wv                     # [T, dv]
scores = Q @ transpose(K) / sqrt(dk)   # [query, key]
for i in range(T):
    for j in range(T):
        if j > i:
            scores[i, j] = -infinity
weights = softmax(scores, axis="key")
Z = weights @ V                # [T, dv]
logits = remaining_network(Z)
loss = cross_entropy(logits, next_token_labels)
```

真实实现通常用广播和矩阵操作构造掩码，不会写上述双重 Python 循环。排查实现时可以检查未来位置的权重是否为零、每个有效行是否归一化，以及修改未来输入后此前位置的输出是否保持不变；比较应关闭 dropout 等随机因素。

**训练与生成只有可用信息不同。** 训练时完整文本已知，所有正确前缀都能并行提供；生成时只知道用户提示，先根据最后位置预测一个 token，将实际抽到的 token 追加，再预测下一个。如果前一步生成错误，后续条件也会改变。这是不能把训练损失直接当成长期生成可靠性的原因之一。

**KV cache 为什么成立，缓存又不能做什么？** 加入一个新 token 后，旧位置仍不能看到它，所以旧位置在各层的表示、key 和 value 不变。推理时可以按层缓存旧 K/V，只为新位置计算新的 Q/K/V，再让新 Q 与全部可见历史 K 匹配。缓存通常具有 batch、head、历史长度、head dimension 等维度；每层保存自己的 K/V，不能用一份跨层共享的缓存替代。

使用缓存可以避免每次重新计算整个历史前缀，但新 token 对历史的注意力仍随历史长度增长，缓存显存也随长度增长。它不会把任意长生成变成总成本线性且显存恒定的过程，也不会扩大 GPT-2 的 1024-token 窗口。若滑动窗口改变绝对位置编号、删改前缀或改变模型参数，旧缓存未必继续有效；训练中还涉及梯度图，不能把推理缓存直接当作通用训练捷径。

最后再区分 padding：如果批处理把短序列补到相同长度，padding mask 应禁止读取补齐位置；补齐查询位置通常还要在损失中忽略。因果 mask 根据 $j>i$ 判断未来，padding mask 根据“是不是有效 token”判断内容，两者可以组合。左侧补齐时还要正确生成位置编号，并避免对全部候选均被遮住的行直接求 softmax。交叉注意力则按源序列有效位置建立可见性，通常不套用同一个目标序列下三角矩阵。[T，§3.1–§3.2；GPT 系列的自回归结构]

## 3 Attention Is All You Need 做了什么

### 3.1 一次完整的翻译怎样完成

以“明天会下雨”翻译为英文为教学例。源文本先分词，再转换成 embedding，并加入位置表示。编码器用多层自注意力和前馈网络，给每个源位置生成融合上下文的表示。解码器接收已经生成的目标前缀，先做因果自注意力，再通过交叉注意力读取编码器输出，最后预测下一个目标 token。直到生成结束标记，翻译完成。[T，图 1；§3.1]

原始 base 模型有 6 层编码器和 6 层解码器，隐藏宽度 512、8 个注意力头、前馈内部宽度 2048。编码器每层包含两个子层，解码器每层包含三个子层。每个子层都有残差连接与 LayerNorm。原论文采用子层输出与输入相加后再归一化的形式：

$$
y=\operatorname{LayerNorm}(x+\operatorname{Sublayer}(x)).
$$

因此，原始 Transformer 与 GPT-2 常见的 Pre-LN 结构不能在示意图中不加说明地混用。Dropout 等细节在上式中省略，但不应据此理解为原模型没有正则化。

### 3.2 前馈网络、残差与位置分别解决什么

注意力主要让不同位置交换信息。逐位置前馈网络对每个位置的特征进行非线性变换：

$$
\operatorname{FFN}(x)=\operatorname{ReLU}(xW_1+b_1)W_2+b_2.
$$

同一层内各位置共享 FFN 参数；不同层使用不同参数。它先扩大通道维度，再压回原宽度，为混合后的信息提供更丰富的非线性处理。[T，§3.3]

残差可以理解为“在原表示上添加修正量”，为深层网络保留直接的信息与梯度通路。LayerNorm 在每个位置的特征维度上进行归一化，帮助维持数值尺度。它不是沿句子长度把不同词归一化在一起。

不带位置线索的全连接自注意力对输入重排具有相应的重排等变性，仅凭 token 内容很难区分“甲追乙”和“乙追甲”的角色顺序。[T] 将不同频率的正弦、余弦位置编码加到词向量上：

$$
PE(pos,2i)=\sin\left(pos/10000^{2i/d_{model}}\right),\quad
PE(pos,2i+1)=\cos\left(pos/10000^{2i/d_{model}}\right).
$$

一种直觉是让每个位置带上多种周期的“坐标刻度”，组合后便于区分位置及相对位移。论文也测试了可学习位置嵌入，效果接近。正弦编码的函数可以计算更长的位置，并不等于模型已经被证明能可靠处理任意长文本。[T，§3.5；表 3(E)]

### 3.3 为什么训练可以并行，生成仍然逐步进行

训练时，完整正确译文是已知的。把目标序列右移一位作为解码器输入，便能在一次前向传播中同时预测各位置的下一个 token；因果掩码确保任何位置都无法提前读取正确答案。这常称为 teacher forcing。

推理时，尚未生成的 token 不存在，因此不能提前填入解码器。模型仍要先生成一个 token，再将它放进上下文预测下一个。**训练的位置并行**与**生成的自回归顺序**同时成立。“去掉循环网络”不能推出“整段自由文本一次生成”。

自注意力使任意两个可见位置在单层中直接交换信息，缩短依赖路径；代价是对长度 $n$ 需要构造 $n\times n$ 关系。注意力核心计算约为 $O(n^2d)$，投影与 FFN 还包括 $O(nd^2)$ 工作。因此“注意力一定比循环网络更便宜”缺少条件：序列长度、隐藏宽度、硬件并行效率和整个层的成本都需要考虑。[T，表 1；§4]

### 3.4 实验怎样支撑结构贡献

论文使用 WMT 2014 英德约 450 万句对、英法约 3600 万句对。base 模型在 8 张 P100 GPU 上训练约 12 小时；big 模型约 3.5 天。训练使用 Adam、前 4000 步学习率 warmup、之后按步数平方根的倒数衰减，并使用 dropout 与标签平滑。[T，§5]

表 2 中，base 模型英德 BLEU 为 27.3，big 为 28.4；big 英法为 41.8。BLEU 依据生成译文与参考译文的 n-gram 匹配评价翻译，分数越高通常越好，但不是“正确翻译的百分比”。这里采用原文摘要与表 2 的英法口径；该 PDF 的 §6.1 仍出现 41.0，来源说明单独记录这一不一致。

论文不仅展示最佳成绩，还改变头数、维度、层数和正则化设置。单头表现逊于合适的多头配置，头数过多也未持续提升；可学习位置嵌入与正弦位置编码接近。这说明整体设计有实验支持，也说明每个设计并非唯一可行解。句法分析实验进一步检验了架构的适用范围，但并不能由此推断“只训练翻译就自动学会所有任务”：句法分析模型仍使用对应训练数据。[T，表 3、表 4；§6]

## 4 GPT-2 把语言模型当作多任务学习器

### 4.1 学习目标为何能与任务发生联系

对 token 序列 $x_1,\ldots,x_T$，自回归语言模型使用概率链式分解：

$$
p_\theta(x_1,\ldots,x_T)=\prod_{t=1}^{T}p_\theta(x_t\mid x_{<t}),\quad
\mathcal L(\theta)=-\sum_t\log p_\theta(x_t\mid x_{<t}).
$$

训练数据本身就提供下一 token 标签，不需要人工逐条标注，所以今天常用“自监督”描述这一训练方式。[G2] 标题中的 unsupervised 并不意味着没有损失函数、标签信号或梯度更新。

教学上可以构造这样的文本：“问题：一周有几天？回答：七天。”如果模型要准确预测“回答”之后的部分，学会某种问答关系就有助于减小损失。互联网上还包含解释、翻译对照、摘要和代码注释等结构。GPT-2 的研究假设是：足够丰富的数据与容量，可能让下一 token 预测同时积累多种任务能力。[G2，§2]

这个假设并非数学保证。模型也可能利用常见表达、局部提示和记忆完成预测；一个全局语言建模目标不保证在有限容量、有限训练下把每项人类关心的能力都学好。真正需要实验回答的是：哪些任务可以迁移，迁移到什么程度，失败出现在哪里。

### 4.2 结构如何从 Transformer 变成 GPT-2

GPT-2 是 decoder-only 语言模型。把原始翻译架构中的编码器和交叉注意力去掉，保留因果自注意力、前馈网络、残差结构与输出预测，便得到理解其主干的一种路径。这里的“decoder”是架构家族名称，并不表示运行时必须有一个对应 encoder。

其输入为 token embedding 加可学习的绝对位置 embedding。典型 block 的简化表达是：

$$
u=x+\operatorname{Attention}(\operatorname{LN}(x)),\qquad
h=u+\operatorname{MLP}(\operatorname{LN}(u)).
$$

MLP 使用 GELU 激活；最后还有 LayerNorm，再映射到词表得分。GPT-2 将归一化放在各子块输入处，并针对深层残差累积调整初始化。[G2，§2.3；架构承接原 GPT]

从张量角度看，长度为 $T$ 的输入先得到 $T\times d$ 表示，经过全部 block 后变成 $T\times V$ 的词表 logits。训练时各行对应不同位置的预测；生成时使用最后一个有效位置的分布抽取下一 token。logits 是未归一化分数，softmax 后才是概率。argmax 倾向选择最高概率，采样可以产生多样输出；改变采样策略不会更新模型知识。

### 4.3 byte-level BPE 怎样兼顾词与字符

若每个完整单词都是一个 token，生僻词、拼写变化和新词会很麻烦；若每个字符或字节都是 token，序列又可能很长。BPE 从小单位开始，逐步合并常见相邻单位，让常见片段变成更大的 token，同时保留表示少见片段的能力。

GPT-2 使用字节层面的 BPE：基础单位可覆盖 256 种字节，最终词表为 50,257。实现会限制跨字符类别的不合适合并，并特别处理空格，减少词表槽位浪费。[G2，§2.2–§2.3]

因此 token 不是“一个英文单词”的同义词，也不是“一个汉字”。某个汉字的 UTF-8 字节可能落入多个 token；英文中空格也可能成为词片段的一部分。byte-level 表示保证任意文本可以编码，不保证各种语言获得相同的训练质量或相同的 token 效率。

### 4.4 WebText 与四种规模

WebText 以 Reddit 上至少获得 3 karma 的外链为入口，用社区筛选作为文档质量的启发式信号。论文使用的早期版本截止 2017 年 12 月，经过清理、去重后有略多于 800 万篇文档、约 40 GB 文本，并排除 Wikipedia，以减少与常见评测语料的重合。[G2，§2.1]

| 论文表 2 参数口径 | 层数 | 隐藏宽度 |
|---:|---:|---:|
| 117M | 12 | 768 |
| 345M | 24 | 1024 |

上下文长度为 1024 token，词表大小为 50,257，batch size 为 512。学习率依据 WebText 的 5% 留出集表现调节。论文指出这些模型在观察范围内仍未充分拟合 WebText。[G2，§2.3；§3]

### 4.5 zero-shot 在 GPT-2 论文中意味着什么

主要意思是：不在目标任务上更新参数，不为每个任务添加专属网络结构，直接测试预训练语言模型。但不同实验仍需要设计输入格式、候选答案评分或解码方式。尤其是翻译和 Natural Questions 实验，论文会提供上下文示例对，以帮助模型识别任务与回答风格。[G2，§3.7–§3.8]

按照 GPT-3 后来明确的 zero/one/few-shot 定义，这些带示例的 GPT-2 设置更接近 in-context few-shot。因此“GPT-2 全部实验没有任何示范”是不准确的；“没有目标任务微调”才是贯穿其研究的关键条件。给提示属于测试设置，是否用验证集挑选提示也关系到评估解释。

### 4.6 结果里既有进步，也有明显边界

| 任务与指标 | GPT-2 最大模型 | 如何解读 |
|---|---:|---|
| WikiText-103 PPL | 17.48 | 跨语料语言建模效果强；PPL 越低越好 |
| LAMBADA accuracy | 63.24% | 包含 stop-word 过滤；无该过滤为 52.66% |
| CBT 普通名词／实体 accuracy | 93.30%／89.05% | 报告验证集；测试集一本书与训练语料重合 |
| Winograd accuracy | 70.70% | 只有 273 个样本，小数据集需谨慎理解 |
| CoQA 开发集 F1 | 55 | 无目标任务微调，但明显落后于强监督系统 |
| CNN/Daily Mail ROUGE-1/2/L | 29.34／8.27／26.58 | 使用摘要提示，整体仅略高于随机抽句基线 |
| WMT14 英→法／法→英 BLEU | 5.0／11.5 | 有翻译行为，但质量有限且方向不对称 |
| Natural Questions exact match | 4.1% | 会回答部分事实问题，整体可靠性很低 |

来源：[G2，表 3–表 4；§3.2–§3.8]。这些指标不能横向当作同一种“能力百分比”：F1 衡量预测与参考答案的匹配，ROUGE 衡量摘要重合，BLEU 衡量翻译重合，PPL 衡量概率预测。PPL 还依赖计量单位与分词口径，不能直接比较不同 tokenization 的数字。

一个原创 PPL 小例子：假设三个正确 token 的预测概率是 0.8、0.5、0.25，平均负对数概率约为 0.768，PPL 为 $e^{0.768}\approx2.154$。它表达平均预测不确定性，不是“三个位置里错了多少个”。

论文在 8 个语言建模数据集中的 7 个上刷新当时纪录，但 1BW 仍落后。摘要中添加任务提示明显改善结果，说明文本前缀确实可以改变行为；摘要仍会混淆细节，说明“被成功唤起的任务形式”与“准确完成任务”是两件事。[G2，§3.1、§3.6]

### 4.7 泛化与记忆必须一起检查

WebText 很大，可能含有评测文本。论文用标准化后的 8-gram 重合检查评测污染，并对 CoQA、LAMBADA 等进一步分析。移除 LAMBADA 的重合样本后，准确率从约 63.2% 变为 62.9%，表明这一检测口径下总体结论变化较小；这不等于训练数据中绝无评测相关信息。[G2，§4；表 6]

“训练与验证损失一起改善”说明整体上仍有欠拟合空间，但不能证明模型从不记忆某些段落。统计泛化和局部记忆可以同时发生。对使用互联网语料的模型，除了报告分数，还应报告去重方法、检测单位、时间截止与重合分析。

## 5 GPT-3 把上下文示范变成系统研究对象

### 5.1 few-shot 的学习发生在哪里

构造一个教学提示：

```text
把物品归入水果或工具。
苹果 → 水果
锤子 → 工具
梨 →
```

模型根据前缀预测“水果”，整个过程只进行前向计算。若把前两行移除，就是 zero-shot 指令形式；保留一个完整示例是 one-shot，保留多个是 few-shot。这里示例是为讲解构造的，不代表论文报告过中文分类成绩。

与微调相比，差别可写成：

$$
\text{微调：}\quad \theta' = \theta-\eta\nabla_\theta\mathcal L_{task};\qquad
\text{上下文学习：}\quad p_\theta(y\mid D_{examples},x).
$$

微调改变参数 $\theta$，上下文学习改变条件输入 $D_{examples}$。上下文可能暂时影响隐藏状态与输出分布，但没有在这一步把示例写回模型权重。新会话移除示例后，那次提示造成的适应不自动保留。[G3，§2；图 2.1]

这不意味着 few-shot 完全不需要任务数据：示例通常仍来自任务的训练集。论文常使用 10–100 个示例，数量取决于能否装进上下文；SuperGLUE 使用 32 个。few-shot 是相对于大规模任务微调而言的少样本使用方式。

### 5.2 模型大在哪里，结构又变了哪里

GPT-3 延续 GPT-2 的自回归目标、Pre-LN、初始化方式与可逆分词，同时在层间交替使用稠密注意力和局部带状稀疏注意力。最大模型有 175B，即 1750 亿参数，96 层、隐藏宽度 12,288、96 个注意力头，每头维度 128，上下文长度为 2048 token。[G3，§2.1；表 2.1]

“局部带状稀疏”限制一个层内部分位置之间的连接；“稠密”层允许更广的前缀信息交互。它仍然遵守因果方向，稀疏模式不等于能读未来。175B 是模型参数量，也不意味着使用混合专家或每次只激活其中很少的专家参数。

论文训练了 125M、350M、760M、1.3B、2.7B、6.7B、13B、175B 共 8 种规模，并在相同任务家族中比较。这样的系列实验比只展示最大模型有说服力：可以观察能力随规模如何变化，而不仅是看到某个大模型偶然取得高分。

### 5.3 数据规模、采样比例与训练量是三个数

| 数据来源 | 可用 token 量 | 论文列出的训练混合权重 |
|---|---:|---:|
| 过滤后的 Common Crawl | 410B | 60% |
| WebText2 | 19B | 22% |
| Books1 | 12B | 8% |
| Books2 | 55B | 8% |
| Wikipedia | 3B | 3% |

来源：[G3，表 2.2]。这里 B 表示十亿；各可用数据量合计约 499B token，**每个模型实际训练消耗 300B token**。权重是原表的近似整数，合计为 101%，不能当作精确概率再声称原表算错。论文按其质量判断提高部分数据的采样频率，并非把所有来源各读一遍。

可以用书架类比：书架上有多少页是可用语料量；读书时怎样挑书是采样权重；最终一共读了多少页是训练 token 量。某本书可以读几遍，另一本书只读一部分。GPT-3 的 WebText2、Books1 和 Wikipedia 因此会被重复采样。[G3，§2.2]

Common Crawl 还经过质量过滤和模糊去重。论文的质量分类器使用精选语料作为正例，优先保留与其更相近的内容。这能改善平均文本质量，也会把精选标准本身的偏好带入训练分布。GPT-3 语料仍主要是英语；论文按词数报告约 93% 英语、7% 其他语言，不能把它当作各语种均衡训练的模型。[G3，附录 A；§3.3]

### 5.4 大规模训练的工程与成本

最大模型 batch size 为约 320 万 token，峰值学习率为 $6\times10^{-5}$。训练使用 V100 GPU 集群，并结合矩阵内部与层间的模型并行，把权重和计算分布到多张设备。[G3，表 2.1；§2.3]

附录 B 给出 Adam 的 $\beta_1=0.9,\beta_2=0.95$，权重衰减 0.1、梯度范数裁剪，以及按 token 计数的学习率 warmup 和余弦衰减。短文档被拼接到 2048-token 序列中，以结束标记分隔，没有为每篇文档额外使用独立的跨文档注意力屏蔽。读者复现训练时需要把这些操作与因果掩码区分开。

附录 D 对最大模型训练计算量估计约为 $3.14\times10^{23}$ FLOPs。它是计算工作量估算，不是 GPU 数量、训练时长、耗电量或美元成本。若只粗算 175B 参数的 FP16 权重存储，约需 350 GB 十进制字节；训练还要保存梯度、优化器状态、激活等，实际所需显存显著更多。这个 350 GB 是教学估算，并非论文给出的部署测量。

### 5.5 结果说明 few-shot 有用，但并非处处有用

| 任务 | Zero-shot | One-shot | Few-shot | 指标与主要来源 |
|---|---:|---:|---:|---|
| LAMBADA | 76.2 | 72.5 | 86.4 | accuracy%，表 3.2 |
| TriviaQA | 64.3 | 68.0 | 71.2 | exact match/accuracy%，表 3.3 |
| Natural Questions | 14.6 | 23.0 | 29.9 | exact match%，表 3.3 |
| CoQA | 81.5 | 84.0 | 85.0 | F1，表 3.7 |
| DROP | 23.6 | 34.3 | 36.5 | F1，表 3.7 |
| RACE-h | 45.5 | 45.9 | 46.8 | accuracy%，表 3.7 |

LAMBADA few-shot 的示例把任务明确为填空，从而帮助模型知道需要生成一个结尾词。one-shot 反而低于 zero-shot，说明“多给一个例子必然更好”不成立；这里提示格式也不同，不能把差值完全归因于示例数量。[G3，§3.1.2]

TriviaQA 的闭卷问答结果较强。闭卷意味着不能另外检索文档，答案主要依赖参数中的知识与提示信息。Natural Questions 同样是问答，却明显更弱，提示“问答能力”并非一个单一、均匀的数值；题型、知识粒度和答案格式都会影响结果。[G3，§3.2]

CoQA 表现较好，但 DROP 的离散推理、RACE 的考试阅读仍有显著差距。SuperGLUE few-shot 测试集综合分为 71.8，高于论文表中的微调 BERT-Large 基线 69.0，低于当时最佳微调系统 89.0。WiC 测试准确率仅 49.4%，接近二分类随机水平；ANLI 也体现出句间比较与推断的困难。[G3，表 3.8；§3.8]

因此，不宜把“175B 语言模型在部分任务达到强结果”改写成“few-shot 全面取代微调”。比较还涉及预训练数据量、总算力、提示选择和模型大小；任务使用样本少，不意味着完整学习过程便宜。

### 5.6 除了排行榜，论文还做了哪些探测

论文对算术、字母重排、新词使用、类比、新闻生成和语法修正等设置额外任务。这些探测试图观察模型在上下文中适应形式或规则的能力。例如短位数算术随规模提升，但更多位数和某些字符串操作仍不稳；能输出正确答案不代表内部执行了一个通用且保证正确的算法。[G3，§3.9]

新闻真假辨识实验说明生成文本可以具有较强表面可信度。其结论受文章长度、样本来源、评估者与实验条件约束，不能延伸为“所有长文本已不可区分”，更不能推出生成内容事实正确。流畅性与真实性应分别评估。

规模曲线显示语言建模损失在研究范围内随计算与规模改善，许多任务也受益。但“在观测范围内呈平滑趋势”不是无限外推定律。不同任务可能平台化、波动或对提示敏感；规模与数据、训练预算一起变化时，因果归因也要谨慎。[G3，图 3.1；§3、§5]

### 5.7 污染、局限与“学习”一词的边界

GPT-3 的训练集过滤存在实现错误，未能清除全部检测到的评测重合；训练成本使重新训练不可行。论文随后构造清洁子集比较分数。大部分任务差异较小，但 Winograd 和 PIQA 被特别标记；部分阅读理解任务的重合只是背景段落，并非问答标签。[G3，§4；附录 C]

后验清洁子集分析有价值，也有边界：移除重合可能改变题目难度，短文本容易误匹配，语义近似重合可能逃过 n-gram 检测。它不能等价于“从未接触评测信息的模型重新测试”。

论文还明确承认，不清楚上下文学习在每个任务上究竟是识别预训练时学过的任务、适应已有任务的新格式，还是在测试时组合出新规则。这是一条连续谱。用几个翻译示例唤起翻译，显然离不开预训练中积累的语言知识；学会一个临时符号映射则可能更多依赖当前上下文。无参数更新是真实的实验条件，内部机制已经完全解释则不是论文结论。[G3，§5]

基础语言模型仍会重复、失去长文一致性、生成不真实内容，且可能保留训练数据的性别、种族和宗教刻板关联。论文讨论了内容滥用、偏见和能源成本。这些议题与技术表现相连：文本越流畅，读者越容易把语言形式误当作事实保证。[G3，§5–§6]

## 6 把三篇工作连起来看

### 6.1 哪些东西保持，哪些发生变化

| 维度 | Transformer 2017 | GPT-2 2019 | GPT-3 2020 |
|---|---|---|---|
| 主体结构 | 编码器＋解码器 | 仅因果解码器 | 仅因果解码器 |
| 注意力 | 双向源端＋因果目标端＋交叉 | 因果自注意力 | 因果稠密与局部稀疏交替 |
| 位置方式 | 主模型正弦／余弦 | 可学习绝对位置 | 承接 GPT-2 的架构方式 |
| 主要训练目标 | 给定源句预测目标句 | 预测下一 token | 预测下一 token |
| 最大模型参数口径 | big 约 213M | 论文 1542M | 175B |
| 数据组织 | 翻译平行句对 | WebText | 多来源混合、质量过滤与去重 |
| 下游使用重点 | 对应任务训练与解码 | 无目标任务参数更新的迁移 | zero/one/few-shot 系统比较 |
| 代表贡献 | 高效序列架构 | 文本任务的隐式迁移 | 规模与上下文适应的实证 |

其中 Transformer 参数数目来自 [T] 表 3，GPT-2 来自 [G2] 表 2，GPT-3 来自 [G3] 表 2.1。三文不是在一个统一评测设置中比赛，因此不应把翻译 BLEU、语言建模 PPL 和 SuperGLUE 综合分放到一条“能力增长”折线上。

从数学上看，监督翻译拟合 $p(y\mid x)$，自回归语言模型拟合 $p(x_1,\ldots,x_T)$，提示把任务、输入和输出写进同一序列，使一段续写能够扮演条件任务输出。这解释了路线如何连起来，也提示它的难点：模型必须同时识别任务格式、找出相关知识、完成推理并遵守答案约束，任一环节失败都可能产生看似合理的错误。

### 6.2 对实现 GPT-2 有什么具体帮助

阅读代码时，可以按一条数据流查找：文本→token ID→token 与位置 embedding→重复 block→最终 LayerNorm→词表 logits→采样→追加 token。对每个张量问三个问题：形状是什么，哪些位置可见，这一步有没有更新参数。

一个最小概念伪代码如下，省略批处理、dropout、缓存与设备处理：

```text
ids = tokenize(prompt)
while 未到停止条件:
    x = token_embedding(ids) + position_embedding(positions)
    for block in blocks:
        x = x + causal_attention(layer_norm(x))
        x = x + mlp(layer_norm(x))
    logits = output_projection(layer_norm(x))
    next_id = sample(logits[last_position])
    ids.append(next_id)
```

生成循环中的权重保持固定。训练则额外计算所有有效位置的交叉熵、反向传播和优化器更新。KV cache 是缓存历史 key/value、减少重复计算的推理优化；它不改变三篇论文讨论的语言建模目标，也不是 GPT-3 上下文学习等同于参数学习的理由。

### 6.3 常见误解与可操作的检查

1. **“attention 是给词语打一个重要性分数。”** 实际上它依赖查询位置、层和头，同一 token 对不同查询的权重可以不同。检查热图的行列含义再解释。
2. **“GPT-2 的零样本就是没有任务提示。”** 论文使用特定格式，部分任务还有示例。检查参数是否更新、提示是否含示范两个维度。
3. **“GPT-3 看了几个例子就重新训练了。”** 论文测试时只前向计算。检查优化器与反向传播是否执行。
4. **“300B token 就是 300B 个英文词。”** token 是分词单位，数据表还区分候选总量与实际训练量。检查单位与采样方式。
5. **“注意力能连所有位置，所以长文本没有成本。”** 连接数量随长度平方增长，模型还受上下文窗口限制。检查时间、显存和位置范围。
6. **“生成得像真人就证明理解正确。”** 表面自然度与事实性可以分离。检查参考答案、推理步骤和反事实变体。

## 7 术语与自测

| 术语 | 在本文中的含义 |
|---|---|
| Token | 分词器使用的离散文本单位，不固定对应词或字 |
| Embedding | 将离散 ID 映射到连续向量的参数表 |
| Logits | softmax 之前的未归一化输出分数 |
| Causal mask | 防止当前位置读取未来 token 的可见性约束 |
| Pretraining | 在广泛语料上学习通用表示与预测能力 |
| Fine-tuning | 在任务数据上继续更新模型参数 |
| In-context learning | 参数固定，用上下文示例影响当前任务表现 |
| Perplexity | 正确符号平均负对数概率的指数，需注明单位 |
| Data contamination | 训练语料包含评测相关信息造成的评估混淆 |

**练习一：** 在手算例子中把三个分数都加上 100，注意力权重是否改变？

答案：不变。分子分母都有相同的 $e^{100}$ 因子，会相消。这也是稳定 softmax 可以减去最大值的原因。

**练习二：** 如果移除 GPT-2 的因果掩码但仍预测下一 token，会发生什么？

答案：训练时模型可能读取后面的正确答案信息，产生信息泄漏；这种训练表现不能代表只有前缀时的真实生成能力。

**练习三：** 一个模型提示中有 20 个问答例子，但没有梯度更新，应叫微调还是 few-shot？

答案：按 GPT-3 的定义是 few-shot in-context learning。示例存在与参数更新是不同条件。

**练习四：** LAMBADA 从 GPT-2 的 63.24% 到 GPT-3 few-shot 的 86.4%，能否全部解释为参数更多？

答案：不能。模型、数据、训练预算与提示设置都发生变化；GPT-2 使用 stop-word 过滤，GPT-3 few-shot 使用填空示范。要做因果比较需控制这些变量。

**练习五：** 把注意力中序列长度加倍、隐藏维度固定，核心得分矩阵的元素数变为多少？

答案：变为四倍。整模型总耗时不必恰好四倍，因为投影、FFN、缓存与硬件效率也参与成本。

**练习六：** GPT-3 为什么会同时“只需少量任务样本”和“预训练样本效率不高”？

答案：前者谈测试时任务适配，后者谈形成这些能力之前消耗的总语料。它们衡量不同阶段，因此可以同时成立。
