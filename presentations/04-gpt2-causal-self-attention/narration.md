# 旁白稿：展开讲讲 Causal Self Attention

## 第 1 页

大家好，这一期我们把 GPT-2 里的 Causal Self Attention 展开讲讲。代码来自 learn-gpt2 项目的 gpt2.py，核心是 CausalSelfAttention 这个类，从第 92 行到第 122 行，一共三十来行。右边这个下三角矩阵就是今天的主角：每个 token 只能看到自己和前面的 token，看不到未来。接下来我们一步一步把它拆开。

## 第 2 页

整个讲解分六个部分。先看注意力在模型里的位置和直觉，再看 c_attn 怎么一次投影出 q、k、v，并切成多个头。然后是打分和缩放、因果掩码和 softmax。接着把多头合并回来，并认识 PyTorch 的 scaled_dot_product_attention。最后看看注意力遇上 KV Cache 时会发生什么。

## 第 3 页

先看注意力在哪里。gpt2.py 第 144 到 147 行是 Block 的 forward：先对 x 做 ln_1，再送进 attn，结果加回 x；再做 ln_2，送进 mlp，同样加回 x，这就是 Pre-LN 残差结构。关键在于，MLP 对每个位置独立计算，不会让 token 之间交换信息。所以在整个 Block 里，注意力是 token 之间唯一交流信息的地方。

## 第 4 页

在看代码之前，先建立一个直觉：注意力就像一张“软”的查找表。每个 token 都有三样东西：query 表示“我在找什么”，key 表示“我拿什么来被匹配”，value 则是“我真正携带的内容”。当前 token 的 query 和每个 key 做点积，得到相似度，经过 softmax 变成一组和为 1 的权重。输出就是所有 value 按这些权重的加权和；和普通查表只取一条不同，它把所有条目按相似度混合起来。

## 第 5 页

这是 forward 的全部代码，从第 101 行到第 122 行，为了看清楚，我们省略了其中的注释。它可以分成五段：第一段用 c_attn 一次投影出 q、k、v；第二段用 view 和 transpose 把它们拆成多个头；第三段在有缓存时，把新的 k、v 写进 kv_cache，并得到总长度 L。第四段根据 T 和 L 的关系，选择三种掩码方式之一，调用 scaled_dot_product_attention；最后一段把多头拼回去，再经过 c_proj 输出。

## 第 6 页

第一步是投影。第 98 行定义了 c_attn，它是一个输入 768 维、输出 2304 维的线性层，2304 正好是 3 乘 768。在 forward 里，第 102 行先取出 B、T、C，第 103 行把 x 送进 c_attn，再用 split 按 n_embd，也就是 768，沿最后一维切成三份。这样每个 token 就同时得到了 q、k、v，三者的形状都是 B、T、768。

## 第 7 页

第二步是切分多头。第 104 到 106 行对 q、k、v 做同样的操作：先用 view 把最后一维 768 拆成 12 个头、每头 64 维，再用 transpose 把头的维度换到前面，形状变成 B、nh、T、hs。这样 12 个头就像 12 个独立的小注意力，每个头只在自己的 64 维子空间里计算相似度和加权。不同的头可以关注不同的关系，最后再把结果拼回去。

## 第 8 页

第三步是打分。每个头里，用 Q 乘以 K 的转置，得到形状为 B、nh、T、L 的分数矩阵，也就是每个 query 对每个 key 的相似度。然后除以根号 hs，GPT-2 里 hs 是 64，所以就是除以 8。为什么要缩放？如果 q 和 k 的每个分量均值为 0、方差为 1，它们的点积方差就是 d_k，数值太大会把 softmax 推进饱和区，梯度变得极小；除以根号 d_k，正好把方差拉回 1。在 gpt2.py 里，这一步藏在 scaled_dot_product_attention 内部，没有传 scale 参数，就用默认的 1 除以根号 E。

## 第 9 页

第四步是因果掩码。分数矩阵里，第 i 行第 j 列如果 j 大于 i，就代表“看未来”，这些位置在 softmax 之前被填成负无穷，softmax 之后权重就变成 0，每一行剩下的权重仍然加起来等于 1。为什么要这样做？第一，生成是从左到右的，生成第 t 个 token 时后面的还不存在；第二，训练时一次前向就能让 T 个位置同时预测各自的下一个 token，并行又高效；第三，推理和训练的行为一致，旧位置的结果不会因为新 token 而改变，所以缓存下来的 K、V 一直有效。

## 第 10 页

第五步是 softmax 和加权求和。左边是掩码之后的分数，未来位置都是负无穷；对每一行做 softmax，负无穷变成 0，剩下的位置变成一组加起来等于 1 的权重，就是右边这张热力图。然后用权重矩阵乘以 V，T 乘 L 的权重乘以 L 乘 hs 的 V，得到每个头的输出，形状是 B、nh、T、hs。直观地说，每个 query 的输出，就是它能看到的那些 value 按权重混合的结果。

## 第 11 页

第六步是把多头合并回来。第 121 行先用 transpose 把头的维度换回去，变成 B、T、nh、hs；但 transpose 只是改了步长，得到的是一个内存不连续的视图，而 view 要求步长兼容，所以先调用 contiguous 复制成连续内存，再 view 成 B、T、C，也就是把 12 个 64 维拼回 768 维。最后第 122 行经过 c_proj，这是一个 768 到 768 的线性层，参数量 590,592，它负责把各个头的信息混合起来。

## 第 12 页

前面几步，在 gpt2.py 里其实都交给了一个函数：F.scaled_dot_product_attention。按照 PyTorch 文档，它等价于先算 q 乘 k 的转置再乘缩放因子，加上掩码，做 softmax，最后乘以 v；不传 scale 时，缩放因子默认是 1 除以根号 E。代码里有三处调用，分别在第 112、115 和 120 行，区别只在掩码怎么给。文档还提到，在 CUDA 上它会根据输入自动选择 FlashAttention-2 或 Memory-Efficient 这样的优化内核，其他后端则使用 PyTorch 自己的 C++ 实现。

## 第 13 页

到这里，单次注意力的计算就讲完了。接下来进入第二部分：当注意力遇上 KV Cache，会发生什么变化。核心思路很简单：旧 token 的 K 和 V 不会再变，可以缓存起来，每一步只为新 token 计算 q、k、v。我们会看到缓存怎么更新，以及代码里那三种掩码分支各自对应什么情况。

## 第 14 页

有了缓存之后，每一步只需要把还没缓存的新 token 送进模型，只为它们计算 q、k、v。第 107 到 109 行：如果传入了 kv_cache，就调用 update，把新的 k、v 追加进缓存，并拿回全部 L 个位置的 K、V，L 等于已缓存的数量加上 T。看表格：prefill 时缓存为空，T 和 L 都等于 prompt 长度 P；decode 时每步只有 1 个新 token，L 是 n 加 1；分块输入时一次喂 T 个，L 就是 n 加 T。update 本身做的事情也很直接：把新 k、v 写进 length 到 end 这一段，更新 length，再返回从 0 到 end 的全部内容。

## 第 15 页

带缓存以后，掩码要按 T 和 L 的关系分三种情况，对应第 110 到 120 行。第一种，T 等于 L，也就是没有缓存或缓存为空，直接用 is_causal=True 的普通因果掩码。第二种，T 等于 1，单个新 token 可以看所有已缓存的位置，所以不需要掩码。第三种是其他情况，比如分块输入：第 i 个 query 的绝对位置是 L 减 T 加 i，所以要用 tril，并把对角线偏移 L 减 T，让掩码对齐到右下角；而 is_causal=True 生成的掩码是对齐左上角的，在这里会挡住本该看到的缓存，这正是代码注释里提醒的问题。

## 第 16 页

最后算一算代价。每个头的分数矩阵是 T 乘 L，打分和加权 V 各需要大约 T 乘 L 乘 hs 次乘加，12 个头合起来就是 T 乘 L 乘 C。prefill 时 T 等于 L，要建一个 T 乘 T 的矩阵；decode 时 T 等于 1，每步只建 1 乘 L 的一行。以 L 等于 1024 为例，有缓存时每个头每层每步只算 1,024 个分数，没有缓存则要重算整个矩阵，下三角就有 524,800 个，全部算是 1,048,576 个。参数方面，每层注意力有 2,362,368 个参数，其中 c_attn 1,771,776、c_proj 590,592，12 层合计 28,348,416。

## 第 17 页

最后用一张形状图把整个流程串起来：输入是 B、T、C，经过 c_attn 变成 B、T、3C，切分成多头后是 B、nh、T、hs；打分得到 B、nh、T、L 的矩阵，softmax 后乘以 V 回到 B、nh、T、hs，合并多头回到 B、T、C，最后经过 c_proj 输出。记住三点：注意力是 token 之间唯一交流信息的地方；因果掩码加 softmax 让每个位置只看过去，而且权重和为 1；有了 KV Cache 之后，按 T 和 L 选择掩码，decode 每步只需要算 1 乘 L 的一行。谢谢观看。
